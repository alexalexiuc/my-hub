# shared services — inventory

One section per domain folder in `packages/shared/src/services/`. Loaded when working in this folder;
read it before adding a query so you reuse what exists. Domains without a section here are small —
read the folder's files directly.

## `src/services/finances/`

- `budgets.ts` — Budget CRUD + access: createBudget, getUserBudgets, getUserActiveBudget, setActiveBudget, getBudgetById, getBudgetDefaultCurrency(budgetId, tx?) (no-auth default-currency lookup, usable inside a DB transaction), getBudgetByIdSystem(budgetId) (no-auth single budget lookup — system-level callers that already have a legitimate acting userId, e.g. snapshotNetWorth), getBudgetMembers, updateBudget, deleteBudget, addBudgetMember, removeBudgetMember, deleteAllUserFinanceBudgets, hasAccessToBudget, enforceBudgetAccess — membership-based access via financeBudgetMembers; getAllBudgetsForSystem() — system maintenance: every budget's id + creator userId (creator can never be removed as a member), for worker jobs that must run against all budgets regardless of report subscriptions; Types: BudgetInsert, BudgetUpdate, UserBudget, BudgetMember
- `accounts.ts` — Account CRUD: createAccount, getAccounts (opts: includeArchived), getAccountById, updateAccount, deleteAccount; getNetWorthHistory(userId, budgetId, limit?) — last N monthly snapshots oldest-first, returns NetWorthSnapshot[]; getAvailableBalanceBreakdown(userId, budgetId) — included non-archived accounts converted to the budget currency at today's rate (native balance + value + rate + rateDate) and the total (liabilities subtracted — classified by `isLiabilityAccount`, so money borrowed counts as a liability at its absolute balance); default: bank+cash included, all others excluded; convertBalanceToDefaultCurrency(balance, accountCurrency, defaultCurrency, opts?) — current-rate reporting view of a balance (falls back to the last transfer rate, else nulls — never throws); updateAccount throws AccountCurrencyLockedError on a currency change once the account has transactions; getAvailabilityPreferences(userId, budgetId) — Map<accountId, include> of explicit user preferences stored in financeAccountAvailability; setAccountAvailableInclusion(userId, budgetId, accountId, include) — upserts or deletes a preference row (no-op if value matches default); deleteAllUserAvailableOverrides(userId) — bulk remove preferences; isIncludedInAvailable(type, preferredInclude) — resolves effective inclusion (preference ?? default); isDefaultIncludedInAvailable(type) / AVAILABLE_DEFAULT_INCLUDED_TYPES / LIABILITY_TYPES — domain constants; getAllAccountIds() — all account IDs (worker only); getLedgerBalances(accountIds, opts?) — single source of truth for "balance computed from the ledger" (transfer destinations credited with to_amount): batched across accounts, optionally date-bounded (opts.asOfDate); no auth, used by recalculateAccountBalance and reporting.ts's getAccountFlows; recalculateAccountBalance(accountId) — recomputes balance from full transaction history via getLedgerBalances (corrections included); returns new value or null; `showOnWidget`/`widgetSortOrder` columns (via AccountUpdate) control a loan account's dedicated card on the finances widget and its order
- `categories.ts` — Group + category CRUD: createGroup/getGroups/updateGroup/deleteGroup, createCategory/getCategories (excludes archived)/getCategoryById/updateCategory/deleteCategory/archiveCategory/unarchiveCategory; `includeInSpendingBudget` column (via CategoryUpdate, default true) controls whether a category's target/spend rolls into the aggregate budget total computed by reporting.ts getBudgetProgress
- `transaction-money.ts` — Multi-currency rules (single owner): resolveTransactionMoney(input) — amount always in the source account currency (input `amountCurrency` converted at user `rate` or the transaction-date market rate, original kept in extras.conversion with rateSource/rateDate), transfers' `toAmount` (destination currency, required when currencies differ unless entered in the destination currency), frozen `reportingAmount` in the budget currency + consistent `exchangeRate`; withConversion(extras, conversion); transferToAmount(t) — destination leg with legacy fallback; transferToAmountSql — SQL twin for aggregates; getOriginalInput(extras) — originally typed amount/currency/rate or null; round4; TransactionMoneyError (UserInputError for invalid money input); corrections get a best-effort reporting value (any known rate, else 0) so they never fail on a missing rate; Types: TransactionMoneyInput, ResolvedTransactionMoney
- `transactions.ts` — Transaction CRUD (money via transaction-money.ts; inputs accept amountCurrency/rate/toAmount, derived rate/reporting/balance fields are never taken from callers; updates re-resolve money only when the money input changes by value): addTransaction, getTransactions (opts: accountId/categoryId/payeeId/type/fromDate/toDate/includeCorrections/search/addedByUserId/limit/offset), getTransactionListItems (same opts; returns TransactionListItem[] with amount/toAmount/reportingAmount, resolved accountName/Currency, toAccountName/Currency, categoryId/Name/Color/Icon, payeeId/Name, groupName, addedByUserId/Initials, createdAt, balances via JOIN), getTransactionListItemById (single TransactionListItem by id; null if not found), countTransactions (same opts), checkDuplicateTransaction (opts: accountId/date/amount (account currency)/payeeId/excludeTransactionId), getTransactionById, updateTransaction, deleteTransaction — all mutating ops update payee stats; Types: TransactionInsert, TransactionUpdate, GetTransactionsOpts, DuplicateCheckOpts, TransactionListItem
- `payees.ts` — Payee CRUD + stats: findPayeeByNameOrAlias, upsertPayee (case-insensitive via normalizedName/aliases), resolvePayeeIdByNameOrAlias (returns id or undefined), updatePayee, getPayees (returns Payee[] with aliases/description ranked by user usage), getPayeeSummary (all-time txCount/totalSpent/totalIncome/avgSpent/firstDate/lastDate/topCategory/topAccount for one payee), deletePayee, incrementPayeeStats, decrementPayeeStats; Types: Payee, PayeeUpdate, PayeeSummary
- `exchangeRates.ts` — Exchange-rate orchestration: getExchangeRateQuote(from, to, date, opts?) — **strict** lookup for every stored amount, returns `{ rate, rateDate }` (exact cache row or API fetch + persist, else nearest cached rate within `maxAgeDays` (default 7, Infinity for display), else throws — never 1.0); getExchangeRate — legacy lenient lookup (recent-row then 1.0 fallback), display-only; ExchangeRateUnavailableError (UserInputError thrown by the strict lookup); Types: ExchangeRateQuote, ExchangeRateQuoteOpts
- `loan-amortization.ts` — Loan amortization helpers: `getMonthlyPayment(principal, monthlyRate, termMonths)` — standard payment formula; `calculateLoanAmortizationSummary(details, opts?)` — schedule-derived + hybrid payment summary using actual payment history; `getLoanBalanceSnapshotForAccount(userId, budgetId, account, opts?)` — remaining principal + amortization summary; `getLoanDisplayBalance(account, loanSnapshot)` — **pure**; resolves the display balance for an account, substituting the amortization-derived remaining principal for interest-bearing loans (raw ledger balance understates remaining principal once payments include interest) — zero-interest loans and non-loan accounts return the ledger balance as-is; `getLoanCardBalance(userId, budgetId, account, opts?)` — fetches the snapshot and resolves it via `getLoanDisplayBalance` in one call; reuse this instead of repeating the snapshot + display-balance pairing in route/UI code; `buildLoanSummary(details, paymentsCompleted, totalPaid, today)` — **pure** closed-form summary (count-based; safe to call without DB for testing); `getLoanSummaryForAccount(userId, budgetId, account, opts?)` — fetches transactions then calls buildLoanSummary; Types: LoanPaymentHistoryEntry, LoanAmortizationSummary, LoanBalanceSnapshot, LoanSummary
- `reporting.ts` — Read-only finance reporting aggregations (every cross-account sum uses the frozen `reportingAmount`, i.e. budget currency; per-account flows stay in the account's currency; net worth converts balances at today's rate and reports rate + rateDate per account): getBudgetProgress (totalBudgeted/totalSpent only count categories with includeInSpendingBudget true; per-category rows are unaffected), getCashflowSummary, getSpendingByPayee (optional categoryId filter), getSpendingAggregates, getComparison (two-period side-by-side comparison with absoluteDelta/percentDelta), getAccountsCashflow(userId, budgetId, dateFrom, dateTo, accountIds?) — Map<accountId, AccountCashflowResult> of income vs spending (expenses + categorized transfers) per account, getSavingsAndDebtFlows(userId, budgetId, dateFrom, dateTo) — SavingsAndDebtFlowsResult of net transfers (in minus out) into Goal/Tracking (savings), Investment, and Loan (debt repayment) accounts for a date range, getAccountFlows(userId, budgetId, dateFrom, dateTo, accountId?) — AccountFlowsResult: per-account opening/closing ledger balance + inflows/outflows/netDelta for a date range, with a `reconciles` flag (false when a correction transaction landed inside the period — corrections are excluded from inflows/outflows but included in the ledger balances), getMonthlyAccountFlows(userId, budgetId, monthFrom, monthTo) — MonthlyAccountFlowsResult: the same inflow/outflow decomposition as getAccountFlows but broken down per calendar month across a window (zero-filled months, per-account totals, each figure in the account's own currency) — powers the Cashflow page's "By Account" view, getSavingsContributions(userId, budgetId, dateFrom, dateTo) — SavingsContributionsResult: net transfers in/out of Goal/Tracking/Investment accounts, per account (as `original`/`converted` `MoneyAmount` pairs — account's own currency vs budget-default-currency-converted, via the transaction's stored exchangeRate) + combined total (always converted-currency), plus the same metric for the immediately preceding period of equal length ("did I actually save this period?"), getNetWorthSummary, snapshotNetWorth(userId, budgetId, month?) — system maintenance: computes getNetWorthSummary (via the internal no-auth computeNetWorthSummary/getBudgetByIdSystem) and upserts that month's row into `finance_net_worth_snapshots` (unique on budgetId+month) — the only writer of that table, intended for a monthly worker job; AccountNetWorth now includes optional `loanSummary: LoanSummary` for loan accounts
- `reports.ts` — Monthly & yearly finance report assembly — composes reporting.ts/accounts.ts/loan-amortization.ts/portfolio.ts building blocks only, no new data-access logic: getMonthlyFinanceReport(userId, budgetId, month?) — cashflow + getAccountFlows + getSavingsContributions + getBudgetProgress, plus insights (category spikes vs trailing-3-month average at a ±40% threshold, payees new in the last 90 days, getAccountFlows `reconciles:false` accounts as data-quality flags, Goal-account progress cross-referenced with savingsContributions, Loan-account paydown this period); getYearlyFinanceReport(userId, budgetId, year?) — cashflow + net worth trajectory (from persisted `finance_net_worth_snapshots` rows within the year — see reporting.ts snapshotNetWorth) + yearly getSavingsContributions + IBKR-equivalent DCA-vs-target (from the standalone Portfolio feature's plannedMonthlyContribution and getSupplies — portfolio.ts explicitly does not feed net worth/financeAccounts, so this is tracked separately from any Investment-type account) + loan payoff progress + 12-month per-category table + year-over-year getComparison; both default to the last completed month/year. Loan paydown for interest-bearing loans uses the pure schedule-derived `calculateLoanAmortizationSummary` (per loan-amortization.ts's documented single-source-of-truth rule); zero-interest loans reuse the already-computed `getAccountFlows` ledger balance instead (every payment is pure principal, so the raw ledger is exact). Types: CategorySpike, LoanProgress, GoalProgress, MonthlyFinanceReport, LoanPayoffProgress, IbkrDcaProgress, YearlyFinanceReport
- `monthly-plans.ts` — Monthly plan CRUD + auto-match: getMonthlyPlan, createMonthlyPlan, checkMonthlyPlanExists, checkMonthlyPlanIsPopulated (true if plan exists AND has items or availableAmount > 0 — ignores auto-created empty plans), getOrCreateMonthlyPlan, getMonthlyPlanFull (plan+items+summary), computeSummary, updateMonthlyPlan (availableAmount and/or incomeAccountId), addPlanItem (overloaded: single → FinanceMonthlyPlanItem, array → FinanceMonthlyPlanItem[]), updatePlanItem (partial update; auto-sets isAssigned when assignedAmount ≥ amount), deletePlanItem, bulkAssignAll, copyToNextMonth (copies to next month; if next month plan is an empty auto-created placeholder, updates it in-place), doesItemMatchTransaction, syncTransactionWithPlan (syncs plan items — assignedAmount in each item's currency — and availableAmount from the frozen reportingAmount on transaction create/update/delete); Types: PlanItemInsert, PlanItemUpdate, MonthlyPlanFull, MonthlyPlanSummary, PlanItemWithMeta
- `portfolio.ts` — Investment portfolio service: getPortfolio, createPortfolio, updatePortfolioSettings, getPositions, upsertPositions, deletePosition (throws if position has buys), addSupply, updateSupply, deleteSupply, getSupplies (events with per-ticker lines), getPortfolioOverview (per-position value/profit with+without fees/allocation deviations + totals + `cadence` contribution-schedule adherence; self-heals price cache), getPortfolioValueHistory (daily {date, value, invested} series with read-time forward-fill), buildPortfolioOverview(portfolio, positions, supplies, latestPrices, fxRates, today)/buildValueHistory (**pure**, exported for tests) — buildPortfolioOverview resolves the cadence anchor as `cadenceAnchorMonth ?? first supply's month` and delegates the math to `computeContributionCadence` in utils/portfolio.ts; Types: PortfolioSettingsUpdate, PositionUpsert, SupplyInput, SupplyWithLines, PositionOverview, PortfolioOverview, PortfolioHistoryPoint
- `tickerPrices.ts` — Ticker EOD price cache: fetchYahooDailyCloses/parseYahooChartResponse (Yahoo unofficial chart API, keyless), fetchStooqDailyCloses/parseStooqCsv (Stooq CSV fallback), getCachedTickerPrices, getLatestTickerPrice, upsertTickerPrices (onConflictDoNothing), ensureTickerPriceHistory (fills only missing head/tail of [fromDate, today]; never throws), getActivePortfolioSymbols (worker-only, distinct symbols + earliest supply date); rows keyed by (yahooSymbol, date) in `finance_ticker_prices` — global cache, trading days only
- `labels.ts` — Label autocomplete service: `getLabels(userId, budgetId)` — list all known label strings for the budget (alphabetical); `syncLabels(userId, budgetId, labels)` — upsert provided label strings into the autocomplete table (no-op if already present). Labels are stored as a string array directly on transaction rows; this table provides autocomplete suggestions only.

## `src/services/calories/`

- `profile.ts` — Calorie profile CRUD: `getCalorieProfile`, `upsertCalorieProfile`, `deleteCalorieProfile`, `deleteAllUserCalorieProfiles`, `generateCaloriesAutomationKey` (generates + persists 64-char hex automation API key). `upsertCalorieProfile` also owns the **goal baseline**: it stamps `goalStartDate`/`goalStartWeightKg` (today + latest `weight` measurement) when the goal is first set, when `goalType`/`goalWeeklyRateKg` change, or when a goal exists without one — and never otherwise, so a projection stays cumulative instead of re-anchoring each week. An explicit baseline in the update always wins (the user resetting it deliberately).
- `meals.ts` — Meal log CRUD: `logMeal`, `getMeals`, `getMealsForDate`, `getMealsForDateRange`, `updateMeal`, `deleteMeal`, `deleteAllUserMeals`
- `day-summaries.ts` — `getDailySummariesForRange(userId, start, end)` — zero-filled per-day `{date, kcal, protein, carbs, fat, mealCount}[]` for a date range, built on `getMealsForDateRange`; used by the Hub Calendar view
- `report-data.ts` — Aggregated report queries: `fetchWeeklyReportCaloriesData`, `fetchMonthlyReportCaloriesData`
- `weekly-menu.ts` — Weekly menu CRUD + day-log tracking: `createWeeklyMenu` (transactional; optionally writes the week's shopping list too), `updateWeeklyMenu` (patch title/prep notes only), `getWeeklyMenus`, `getWeeklyMenu`, `getWeeklyMenuByWeek`, `addMealToMenu`, `updateWeeklyMenuMeal`, `upsertMenuMeal` (insert-or-overwrite a slot; clears its day-log), `deleteWeeklyMenuMeal`, `deleteWeeklyMenu`, `deleteAllUserWeeklyMenus`, `hasAccessToMenu`, `logMenuMeal` (transactional journal entry + day-log marker), `unlogMenuMeal` (undoes both, in one transaction), `getLoggedDays`, `getMenuStatusForRange(userId, start, end)` — per-date `{hasMenu, logged}` for a date range in 3 batch queries, used by the Hub Calendar's menu icon. No marker-only "mark as logged" helper exists — writing a day-log without its journal entry is the desync `logMenuMeal` is built to prevent.
- `shopping-list.ts` — Weekly-menu shopping list CRUD: `getShoppingListItems`, `addShoppingListItems` (bulk append, trim + case-insensitive dedupe), `replaceShoppingListItems` (clear + insert whole list in a tx; AI-authored write path), `setShoppingListItemChecked`, `deleteShoppingListItem`, `deleteAllUserShoppingListItems`

## `src/services/vacation/`

- `data.ts` — `getVacationProfile`, `loadVacationModel(userId, { includeDraftRules, includePlanned })` (narrows rule sets to the profile's country/region, tax regimes to its employer, holidays to national + the profile's locality with the regional row winning, then builds the engine model; throws without a profile) `deleteAllUserVacationData`, `VacationValidationError` (a `UserInputError` for invalid vacation input or missing setup)
- `demo.ts` — `buildVacationDemo(today)` — pure demo profile + engine input (MD rules incl. 2027 draft, six months of salary with bonuses, a projected raise, one taken and one planned leave, `moldovaPublicHolidays` for the range). `loadVacationModel` uses it when `allowDemo` is set and the user has no profile; results then carry `demo: true` and no warnings. Hub routes opt in, MCP does not
- `setup.ts` — `applyVacationSetup(userId, changes)` — one validated transaction over profile, rule sets (by id), tax regimes (by id, MD default rates per regime), salaries (by month, stored as the 1st), holidays (by date + country + region; a `manual` row is never overwritten by `research`); rejects overlapping rule sets per country+region+status and tax regimes per employer before writing anything. `applyLeaveChanges(userId, { upsert, remove })` — leave periods may not overlap
- `queries.ts` — `getVacationCalendar`, `evaluateVacationSpan`, `getVacationBalance`, `findBestLeaveWindows` (validates the leaveDays/restDays × objective combination), `getVacationConfig(userId, today)` (profile, rule sets, regimes, leave periods, salary coverage incl. missing months, holiday coverage per year, gap warnings)
